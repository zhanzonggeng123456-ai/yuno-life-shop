# Yuno Life — 日本本地中古交易平台(第一、二、三阶段 + 在线版功能回迁 + 商业级优化)

AI 驱动、全品类、支持多种交易模式的中古交易平台。
首期运营区域:埼玉县坂户市,后续可扩展至鹤岛、川越、东松山。
货币 JPY,时区 Asia/Tokyo。

## 已实现(第一阶段 12 项)

1. 用户注册登录:邮箱注册、PBKDF2 密码哈希、会话 Cookie、
角色(普通/收藏品卖家/运营/鉴定审核/配送/管理员)服务端强制校验。
2. 全品类商品发布:13 大类,每类有自己的属性字段(属性定义 JSON,
可扩展),例如手表:品牌/型号/机芯/年份/表径/附件/维修记录;
钱币:国家/年代/面额/材质/评级机构/分数/真伪状态。
3. 图片上传:本地存储 `uploads/`,5MB 以下、jpg/png/webp/gif。
4. AI 辅助分类与商品介绍生成:本地启发式规则(关键词 + 本地历史数据),
生成日文+中文标题/介绍/规格/成色描述/关键词/参考定价草稿,
用户确认修改后才能发布。估价给参考区间、可信度与依据;
数据不足时明确提示暂无样本,绝不编造市场成交价。
真实大模型 API 只留可替换接口,默认关闭(见下)。
AI 一键链路(入口:交易面板 / `/oneclick`,三步每步一个主按钮,
移动端可用):第 1 步上传照片 → 第 2 步一键识别 → 第 3 步一键上架。
识别(类别/品牌/型号/材质/成色)、鉴定(成色等级与真伪风险提示)、
估价(参考区间/可信度/依据)全部是本地启发式推测,全部可人工修改,
绝不把推测当事实;高价值商品(手表/钱币/古董且 ≥100000 日元)自动进
人工复核队列,通过前不可交易,结论与复核记录写入审计;无足够样本时
明确提示缺少可靠成交样本,不得编造价格;点“一键上架”就是用户确认,
发布后走正常商品/订单/库存流程。真实视觉模型只留接口占位,默认关闭。
5. 商品浏览、搜索、筛选:关键词、分类、地区、价格区间、自营筛选。
6. 固定价格 C2C 交易:固定价直接购买、站内沟通、买家出价/
卖家接受/拒绝/还价。
7. 站内消息:按(商品,买家)分线程,买卖双方可见,无关用户 403。
8. 平台买断申请:提交 → AI 参考区间 → 平台审核 → 平台报价 →
用户接受 → 预约取货 → 验货 → 收购付款 → 进入自营库存,
记录实际收购成本。平台有权拒绝收购,不承诺全收;
报价参数后台可调,绝非固定比例。
9. 自营商品管理:平台自营标识、今日特价、精选、成色等级、
检测记录、库存、成本毛利统计,与第三方商品明确区分。
10. 基础订单系统:订单状态机、佣金计算、模拟支付接口、
金额变动审计。模拟支付在界面和代码里明确标注,
不得宣称为真实完成;支付回调模拟支持幂等键。
11. 基础后台:用户、商品、分类、买断申请与报价审批、自营库存、
订单、佣金收入、成本利润统计。利润严格区分 GMV、
商品销售额、自营毛利、费用、经营利润、净利润,
不把平台代收交易额误算成收入。
12. 语言三档:中文 / 日本語 / 跟随系统(按 Accept-Language:zh→中文、ja→日语、其他→日语默认);手动选择写 cookie 持久化,切换立即全界面生效;英文键保留作回退。

## 零 API 成本本地运行方式(硬约束)

本 MVP 全程本地跑,零 API 成本:

- 数据库:SQLite 本地文件(`data/yuno.db`),无云数据库费用。
- 图片:本地磁盘存储(`uploads/`),无对象存储费用。
- AI 辅助:本地启发式规则(关键词匹配 + 本地历史成交/挂牌统计),
不调用任何第三方大模型 API,零 token 费用。
- 支付:本地模拟支付(明确标注),无支付手续费、无开户费。
- 短信/物流:未接入,本地流程用站内消息与人工预约时间代替。
- 依赖:仅 FastAPI / Uvicorn / python-multipart / httpx / pytest,
全部免费开源,无按量计费服务。

## 未来每接一个外部服务会产生什么成本

| 服务 | 接入后成本形态 | 状态 |
| --- | --- | --- |
| 真实 AI 模型 API | 按 token 计费,随调用量增长;需设置预算上限 | 占位接口,默认关闭 |
| 真实视觉模型 API(拍照识别) | 按调用量计费,随调用量增长;需设置预算上限 | 占位接口,默认关闭,一键链路只走本地启发式 |
| 持牌支付服务商(日本) | 开户/月费 + 每笔手续费(以服务商报价为准) | 模拟支付,待接入 |
| 短信验证 | 按条计费 | 未接入,邮箱注册代替 |
| 对象存储 | 按存储量 + 流量计费 | 本地存储,待接入 |
| 物流服务 | 按单计费 | 人工预约代替,待接入 |

原则:接了才花钱,不接也能跑。任何外部服务接入前都需用户批准。

- 交易行情系统(`/market`):各类别交易量、今日热门、热门交易榜 TOP 10、

挂牌价与真实成交价严格区分,演示订单一律排除,数据不足时显示样本量与提示。
- 分类热门榜单、价格曲线、收藏品专属属性及行情(手表/钱币/古董三类
成交均价 vs 在售挂牌均价对照)。
- AI 运营 Agent(全部本地启发式,零 API 成本):商品审核、定价辅助、
商品分类、客服规则问答、订单异常监控、交易纠纷辅助、库存与定价优化、
经营数据分析;高风险操作(收购付款、封禁、争议裁决)只接受人工审批,
建议与裁决均写入审计记录。
- 自营库存动态定价:只给调价建议(库存天数、关注数、同类挂牌价中位数),

- 经营利润分析(`/admin/profit`):营业额、GMV、商品销售额(C2C/自营分列)、

- 异常交易预警:恶意竞价(出价跳涨)、重复支付、虚假订单(同一买家多笔
待付款)、账户异常(频繁取消),后台一键扫描并确认处理。

## 移植新增(在线版功能回迁)

- 导航:无顶部导航,底部 5 按钮(市场/成交行情/交易/订单/个人中心);
交易面板 /trade;规则页 /rules 等;页脚含含税与模拟结算标注。
- 发布相机优先 + 多图:文件选择 capture="environment"(后置摄像头)与相册并列,
拍照后即时预览;每件商品最多 10 张,首张为封面(可点切换),每张可预览/删除/
替换/重拍;AI 分析用全部照片;详情页展示全部照片;无照片时估价入口置灰。
- 鉴定两轴:敏感品类(手表/钱币/古董/品牌包袋/模型收藏)给成色 + 真伪结论,
细节清单只是建议,细节不足→低置信度 + 注明,不硬说无法确认,红旗/高价值
进人工复核,结论一律标注 AI 推测;普通品类(家电/家具等)只给成色,不做真伪判断。
- 估价:照片后恒返回区间,偏保守低位(新品 ¥15,000 的二手上限约 ¥7,500 随成色浮动,
绝非固定比例);以用户确认的精确型号在真实市场的同型号挂牌/成交价为依据,
平台自身数据不进入计算;展示依据 + 样本量 + 置信度,标注 AI 参考价;
区间下方逐字免责“此报价为AI根据现实数据做出的估价，用户可以根据自身另行填写”;
市场区间中位数自动填入可编辑草稿,发布需确认;型号未确认或无同型号市场价时
如实说明,绝不编型号编价格;启发式只作单独标注的推算参考。
- 市场搜索:按精确型号并行查 Mercari/Yahoo 拍卖/Rakuma/PayPay/eBay
(图书 Amazon 二手/BOOKOFF,手表 Chrono24 优先),硬上限 60 秒,超时/不可达/
无结果明说,8–10 样本提前结束,同型号 24 小时缓存,60 秒后后台继续跑并写缓存;
搜索页摘要提取,站点反爬时按不可达/无结果返回,绝不编造。
本地无视觉模型、无 OCR 库:识别与鉴定为本地启发式 + 用户确认/手动修正,
结论均标注推测性质。
- 行情双榜:/market 涨幅与下跌同屏双榜,按单个商品,绿▲/红▼胶囊,上下数量,
最高涨/跌突出;依据为 ≥2 笔真实订单的首次 vs 最近成交价并标注样本量,
不足的排除并明示;挂牌价不计入涨跌;本榜是平台行情展示,与估价的市场搜索数据不同。
- 后台任务:ai_jobs 表 + POST /ai-jobs 派发 + GET /ai-jobs/{id} 轮询
(queued→running→done/failed,仅所有者或运营可见);oneclick 识别/估价与市场搜索
可走任务;同步型号确认只读缓存,实时搜索走任务。
- 规则与说明:/rules、/terms、/privacy、/returns、/prohibited 双语可读,
页脚与个人中心可达;价格含税说明;模拟结算标注贯穿。
- /ai-assist 收口:平台订单参考一律标注“平台订单参考(不是市场价)”,
用户-facing 估价不再把平台数据说成市场价。

## 商业级优化

- 安全:服务端权限复核(议价/消息/关注等越权与空对象 500 已修);
注册 role 参数忽略、口令 ≥8 位、邮箱格式、昵称 ≤50 字;输入校验
(价格 ≥1、服务小时 (0,24]、件数 1–100、文本长度上限,非法 400);
限流(登录失败 10 次/10 分钟、注册同邮箱 10 次/10 分钟、改角色 20 次/10 分钟,
超限 429,成功登录不计数);审计覆盖(改角色、上下架、参数、费用、买断、
订单支付/完成/取消、服务、配送、拍卖结算、调价驳回、Agent 运行);
会话 cookie SameSite=Lax + Origin 不一致拒绝(完整 token 式 CSRF 仍为遗留项)。
- 数据完整:支付幂等(同一幂等键重放与二次提交均 already_paid,审计与 intent 各 1 条);
重复购买/保证金拒绝;终态(已完成/已取消/已退款、已结算拍卖、被拒买断)不可逆;
已支付订单仍可取消属原状态机既定流转(不在终态之列),予以保留。
- 合规与体验:商品/订单/拍卖/买断/服务详情显式含税行与模拟标注;
移动端图片自适应、表格横向滚动、长词断行;404/403/401 友好页;
爬链测试覆盖四种身份无死链;无占位文案。
- 生产数据干净:启动不自动 seeding;演示数据(demo=1)排除经营统计、价格参考与行情关注;
利润表退款合计口径修正为“已裁决且批准”。

## 已知局限(上线前必须处理)

- 完整 token 式 CSRF 未实现:现有 SameSite=Lax + Origin 校验作纵深防御,
完整方案需逐表单加 token 并同步更新全部 POST 测试,公开部署前建议补上。
- 图片内容审核未实现:公开前需补。
- 模拟支付不是真实收款:正式运营必须接入持牌支付服务商,
且不得自行建立未经许可的资金托管业务。
- 真实收款是唯一真正需要用户在外部办理的事项:
与日本持牌支付服务商签约开户,取得商户号与 API 密钥,
配置回调地址并完成分账/退款报备(详见 docs/PENDING.md)。
