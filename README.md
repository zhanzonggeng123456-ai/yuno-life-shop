# Yuno Life — 日本本地中古交易平台(第一、二、三阶段已实现)

AI 驱动、全品类、支持多种交易模式的中古交易平台。
首期运营区域:埼玉县坂户市,后续可扩展至鹤岛、川越、东松山。
货币 JPY,时区 Asia/Tokyo。

## 一条命令启动

```bash
./start.sh
```

首次运行自动创建虚拟环境并安装依赖,然后打开
http://127.0.0.1:8000

也可以手动运行:

```bash
python3 -m venv.venv &&.venv/bin/pip install -r requirements.txt
.venv/bin/python run.py
```

演示数据(明确标注 DEMO):

```bash
YUNO_SEED_ADMIN_PASSWORD=你设的口令 YUNO_SEED_SELLER_PASSWORD=你设的口令 \
YUNO_SEED_BUYER_PASSWORD=你设的口令 .venv/bin/python -m app.seed
# 管理员: admin@yuno.local(口令来自环境变量 YUNO_SEED_ADMIN_PASSWORD,部署后立即修改)
# 演示口令不写进代码:三个演示账号的口令必须用环境变量传入,未设置则种子脚本直接报错退出
# 重置演示数据:同上命令加 --reset
```

运行测试:

```bash
.venv/bin/python -m pytest tests/ -q
# 27 项全过:8 项第一阶段 + 12 项第二、三阶段 + 7 项 AI 一键链路
# (拍卖全流程/代理出价/延时/流拍/一口价/保证金、评价、配送、服务订单、
# 退款争议、高价值审核、行情真实数据、Agent、利润分析、新功能权限、
# 识别可改/无样本不编价/高价值自动复核/一键上架成单/越权拒绝)
```

## 已实现(第一阶段 12 项)

1. 用户注册登录:邮箱注册、PBKDF2 密码哈希、会话 Cookie、
角色(普通/收藏品卖家/运营/鉴定审核/配送/管理员)服务端强制校验。
2. 全品类商品发布:13 大类,每类有自己的属性字段(属性定义 JSON,
可扩展),例如手表:品牌/型号/机芯/年份/表径/附件/维修记录;
钱币:国家/年代/面额/材质/评级机构/分数/真伪状态。
3. 图片上传:本地存储 `uploads/`,5MB 以下、jpg/png/webp/gif。
4. AI 辅助分类与商品介绍生成:本地启发式规则(关键词 + 本地历史数据),
生成日文+中文标题/介绍/规格/成色描述/关键词/参考定价草稿,
用户确认修改后才能发布。估价给参考区间、可信度与依据;
数据不足时明确提示暂无样本,绝不编造市场成交价。
真实大模型 API 只留可替换接口,默认关闭(见下)。
AI 一键链路(入口:导航“AI一键发布”/ `/oneclick`,三步每步一个主按钮,
移动端可用):第 1 步上传照片 → 第 2 步一键识别 → 第 3 步一键上架。
识别(类别/品牌/型号/材质/成色)、鉴定(成色等级与真伪风险提示)、
估价(参考区间/可信度/依据)全部是本地启发式推测,全部可人工修改,
绝不把推测当事实;高价值商品(手表/钱币/古董且 ≥100000 日元)自动进
人工复核队列,通过前不可交易,结论与复核记录写入审计;无足够样本时
明确提示缺少可靠成交样本,不得编造价格;点“一键上架”就是用户确认,
发布后走正常商品/订单/库存流程。真实视觉模型只留接口占位,默认关闭。
5. 商品浏览、搜索、筛选:关键词、分类、地区、价格区间、自营筛选。
6. 固定价格 C2C 交易:固定价直接购买、站内沟通、买家出价/
卖家接受/拒绝/还价。
7. 站内消息:按(商品,买家)分线程,买卖双方可见,无关用户 403。
8. 平台买断申请:提交 → AI 参考区间 → 平台审核 → 平台报价 →
用户接受 → 预约取货 → 验货 → 收购付款 → 进入自营库存,
记录实际收购成本。平台有权拒绝收购,不承诺全收;
报价参数后台可调,绝非固定比例。
9. 自营商品管理:平台自营标识、今日特价、精选、成色等级、
检测记录、库存、成本毛利统计,与第三方商品明确区分。
10. 基础订单系统:订单状态机、佣金计算、模拟支付接口、
金额变动审计。模拟支付在界面和代码里明确标注,
不得宣称为真实完成;支付回调模拟支持幂等键。
11. 基础后台:用户、商品、分类、买断申请与报价审批、自营库存、
订单、佣金收入、成本利润统计。利润严格区分 GMV、
商品销售额、自营毛利、费用、经营利润、净利润,
不把平台代收交易额误算成收入。
12. 日语及简体中文界面切换(`?lang=ja|zh|en`),英文键已预留。

## 零 API 成本本地运行方式(硬约束)

本 MVP 全程本地跑,零 API 成本:

- 数据库:SQLite 本地文件(`data/yuno.db`),无云数据库费用。
- 图片:本地磁盘存储(`uploads/`),无对象存储费用。
- AI 辅助:本地启发式规则(关键词匹配 + 本地历史成交/挂牌统计),
不调用任何第三方大模型 API,零 token 费用。
- 支付:本地模拟支付(明确标注),无支付手续费、无开户费。
- 短信/物流:未接入,本地流程用站内消息与人工预约时间代替。
- 依赖:仅 FastAPI / Uvicorn / python-multipart / httpx / pytest,
全部免费开源,无按量计费服务。

## 未来每接一个外部服务会产生什么成本

| 服务 | 接入后成本形态 | 状态 |
| --- | --- | --- |
| 真实 AI 模型 API | 按 token 计费,随调用量增长;需设置预算上限 | 占位接口,默认关闭 |
| 真实视觉模型 API(拍照识别) | 按调用量计费,随调用量增长;需设置预算上限 | 占位接口,默认关闭,一键链路只走本地启发式 |
| 持牌支付服务商(日本) | 开户/月费 + 每笔手续费(以服务商报价为准) | 模拟支付,待接入 |
| 短信验证 | 按条计费 | 未接入,邮箱注册代替 |
| 对象存储 | 按存储量 + 流量计费 | 本地存储,待接入 |
| 物流服务 | 按单计费 | 人工预约代替,待接入 |

原则:接了才花钱,不接也能跑。任何外部服务接入前都需用户批准。

## 已实现(第二阶段)

- 拍卖竞价:起拍价、保留价、最小加价、开始/结束时间、实时最高出价、
自动代理出价、竞价记录、结束前 5 分钟内出价自动延时 5 分钟、
竞拍资格验证、可选保证金(模拟托管)、流拍处理、拍卖结束自动生成
待付款订单、一口价;与固定价交易共用商品/用户/支付/订单体系。
- 交易评价:订单完成后买卖双方互评,用户主页展示平均评分与评价数。
- 配送预约:买家申请本地配送、卖家申请上门取件、服务时间预约、
配送任务管理、取货/交付照片留存、买家交付确认;运费沿用
轻小件 150 日元起按尺寸分档、XL 单独报价、不承诺全能送达。
- 增值服务订单(独立体系):家居清洁(2,000 日元/小时,可配置)、
商品清洁整理、商品检测、商品拍摄及代上架、上门估价、小件搬运、
商品代售;与买断同笔结算时分项列示应收、应付与抵扣净额。
- 退款和争议机制:申请、举证、运营人工裁决、裁决写入审计记录;
批准退款后订单状态变为 refunded 并记账。
- 高价值收藏品审核:手表/钱币/古董且 >=100,000 日元自动进入审核队列,
身份验证标记 + 人工鉴定流程,鉴定通过前不可交易。
- 支付服务商接口层:`app/payments.py` 提供持牌服务商接入点、
回调幂等、分账/退款接口占位;默认仍走明确标注【模拟】的本地模拟,
模拟订单绝不宣称为真实收款。真实收款需用户自行完成的事项见
docs/PENDING.md(商户签约),软件不代注册、不花钱。

## 已实现(第三阶段,全部基于真实订单,绝不编造)

- 交易行情系统(`/market`):各类别交易量、今日热门、热门交易榜 TOP 10、
最近成交价格区间、历史价格走势(最近 12 周)、收藏品价格变化、
关注人数、挂牌数量、成交数量、成交周期、类别活跃程度;
挂牌价与真实成交价严格区分,演示订单一律排除,数据不足时显示样本量与提示。
- 分类热门榜单、价格曲线、收藏品专属属性及行情(手表/钱币/古董三类
成交均价 vs 在售挂牌均价对照)。
- AI 运营 Agent(全部本地启发式,零 API 成本):商品审核、定价辅助、
商品分类、客服规则问答、订单异常监控、交易纠纷辅助、库存与定价优化、
经营数据分析;高风险操作(收购付款、封禁、争议裁决)只接受人工审批,
建议与裁决均写入审计记录。
- 自营库存动态定价:只给调价建议(库存天数、关注数、同类挂牌价中位数),
运营在后台确认后才生效,生效记录写入审计。
- 经营利润分析(`/admin/profit`):营业额、GMV、商品销售额(C2C/自营分列)、
商品毛利、服务收入、退款合计、实际费用、经营利润、净利润严格区分。
- 异常交易预警:恶意竞价(出价跳涨)、重复支付、虚假订单(同一买家多笔
待付款)、账户异常(频繁取消),后台一键扫描并确认处理。

## 已知局限(上线前必须处理)

- 未实现 CSRF token:公开部署前必须加上。
- 未实现速率限制与图片内容审核:公开前需补。
- 模拟支付不是真实收款:正式运营必须接入持牌支付服务商,
且不得自行建立未经许可的资金托管业务。
- 真实收款是唯一真正需要用户在外部办理的事项:
与日本持牌支付服务商签约开户,取得商户号与 API 密钥,
配置回调地址并完成分账/退款报备(详见 docs/PENDING.md)。
